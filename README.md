# LinkBlock

受经典画线圈地玩法启发的十关卡网页小游戏。开场随机矩形是玩家唯一的初始小岛；沿岛岸移动，按住空格离岸画线，再回到岛岸完成闭合，圈内并入小岛并显露山水。裸露场地外框仅限制出界，不能作为额外岸线；小岛已经覆盖到外框的真实边缘仍可正常通行。圈住普通敌人即可击败，圈住 Boss 扣一格血并触发逃离跳跃。净化进度达到 75%（人物区域占 60%、背景占 40%），或耗尽 Boss 的 5 格血，均可获胜。三条生命耗尽则结束。美术和音频资源随项目提供，无需外部图片服务或后端。

三个阶段分别在 5–4、3–2、1 血生效。第二至第五关的发射间隔依次为 5.2/4.4/3.6、4.4/3.7/3.0、4.2/3.5/2.9、4.0/3.3/2.7 秒；第六至第十关依次为 4.4/3.8/3.2、4.2/3.6/3.0、4.0/3.4/2.9、3.9/3.3/2.8、4.1/3.4/2.8 秒。第二关起预警至少 1 秒。瞄准弹幕在预警开始时锁定角度，发射后不追踪；屏幕预警与实际发射共用同一组角度，减少动态效果时也保留预警。

前四关的小怪保持匀速，不使用突然加速；第五关首次引入慢行 / 冲锋循环。第一至第五关的初始数量与全程上限依次为 **6 / 7 / 8 / 9 / 10 只**（不含 Boss），三类小怪的配比为 2+2+2、3+2+2、3+3+2、3+3+3、4+3+3。Boss 二阶段起才补怪，间隔依次为 **6 / 5.5 / 5 / 4.5 / 4 秒**，每次最多补 1 只；三阶段沿用同一数量上限，不因残血继续堆怪。无安全位置时跳过本次，不积攒补怪批次。

小怪不追踪玩家，仍受真实未占领区域边界约束；采用冲锋的第五、十关先以基础速度 45% 慢行，再以 170% 冲锋。各怪节奏独立，补怪也沿用本关运动规则。第六至第十关保留初始 13/14/15/16/17 只，二阶段补到 `8 + 关卡编号` 只，三阶段补到 `13 + 关卡编号` 只；基础速度为第一关的 1.24/1.28/1.32/1.36/1.40 倍。所有关卡遵守安全生成、场地容量与 32 只全局上限。

玩家标记是没有动物特征的金色灵火，四帧按每秒 6 帧循环；亮芯固定在角色坐标上，短尾随最后的移动方向旋转，暂停时冻结，减少动态效果时固定首帧。暂停、结果、选关、图鉴和攻略弹窗统一使用透明缺口的破损羊皮纸。

主界面沿用旧书背景，放大 Logo 并用浅色纸纹衬底提高辨识度；桌面左右分栏，手机上下排版。羊皮纸菜单突出开始按钮，其他四个入口排成两列，封印进度集中在底部。方向键 / WASD 按菜单网格移动，Tab 与设置里的原生键盘操作仍可使用；小屏展开设置后可滚动。

`review/rewards.html` 展示全部 30 张通关、90% 和无伤图片；`review/enemies.html` 展示 10 个 Boss、50 个小怪和玩家四帧预览。两页都按当前 `LEVELS` 导出，点击图片可放大和保存原图。放大后支持左右按钮、键盘方向键和手机横向滑动，显示当前张数；筛选关卡后只在该关内循环，标题和下载链接随当前图片更新。开发启动与构建会重新生成；运行 `node scripts/export-art-review.mjs --offline /absolute/output/folder` 可另存两份内嵌图片、无需联网的 HTML，保留相同切图功能。

关卡配置在 `src/levels.ts`，定向弹幕在 `src/level-attacks.ts`，运动规则在 `src/enemies.ts`。`gameOptionsFor` 是页面初始进入、选关、重开和下一关共用的配置入口。基础碰撞、受击保护、暂停、跳跃及胜负清场规则保持共用。

验证：`npm test` 覆盖预警锁定、真实圈地切换阶段、补怪继承规则、暂停、重开、连续运动、十关连续解锁与奖励持久化；`CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e -- tests/level-combat.spec.ts tests/progress.spec.ts tests/expansion.spec.ts` 覆盖十关在桌面、竖屏、窄屏和横屏上的选择、弹幕、攻略与重开，以及首次进入、旧存档升级、实际资源加载、下一关和最终通关。

## 操作

| 操作 | 按键 |
| --- | --- |
| 四方向移动 | 方向键 / WASD |
| 画线 | 按住空格并移动 |
| 逐段收线 | 按住画线键，沿当前线段反向移动 |
| 快速收线 | 未闭合时松开空格 |
| 暂停 / 继续 | P / Escape |
| 重新开始 | R |

手机竖屏提供模拟手柄：上方是游戏画面，下方默认是单手自由触控区，底部“切换操作方式”依次切换双手方向在左、双手方向在右，再回到单手自由触控。双手模式的圆键按住即画线，松开即收线，支持与方向键同时触摸。单手模式在下方接近整页宽的矩形区域内任意位置按下，即进入画线准备状态，以本次触点为手势初始点；方向来自相邻触点的滑动位移向量，不由当前触点相对圆心的位置或圆盘分区决定。手指向哪边滑就向哪边走，转向无需先回中心；停住手指时保持最后方向，松开或触摸取消时停止并回收未闭合轨迹。小于 3 个 CSS 像素的位移先累计，过滤来回微抖而不丢失缓慢滑动；斜向位移以稳定的主轴映射为四方向，角色仍按连续坐标走正交线。圆环在按下位置显示，摇杆帽只显示相对本次初始点的位移并限制在圆环内；手指拖出矩形仍通过指针捕获持续读取位移，直到松手或取消。只有最先按住的那根手指控向，暂停、重开和模式切换在触控区之外。模式切换、重开、失焦和取消会清除前一触点及方向，下一次按住不移动不会继承旧方向。双手方向判定以十字键中心划分四个 90 度扇区，透明触摸范围比原十字键向外扩大 18 像素，外观不变。按住滑动可连续切换方向，无需抬手；中心 12 像素内停住，滑出扩展圆形范围时停止，保持按住后滑回即可继续；宽屏和横屏隐藏手柄。竖屏布局适配安全区并锁定页面滚动，屏幕下方保留暂停、重开和 Boss 血量。整个游戏页面（包括顶端标识、标题、说明、游戏画面、状态栏及手柄）禁止长按选字、链接/图片长按菜单和原生拖拽；使用 Safari 的防选中与长按菜单样式，并拦截选择、菜单与拖拽事件，不拦截整页触摸或滚动。按钮保留键盘焦点和辅助阅读，真实输入框、下拉框及可编辑内容保留编辑、选字与原生菜单，输入时游戏快捷键不会抢占按键。普通移动只能沿已揭示小岛的真实外轮廓行走，包括小岛贴着地图边缘的部分；不能穿过岛屿内部，或把未被小岛覆盖的外框当作岸线，即使按住画线键也不例外。圈地闭合后保持当前方向，在前方仍为有效岛岸时连续前进，保留本帧未消耗的移动距离；若整个独立区域被清空、连接点也消失，则接回最近的剩余边界并更新收线锚点。真正的拐角仍需转向，闭合不会清空持续按住的键盘或触控方向。键盘与触屏均按帧经过的时间连续移动，速度为每秒约 256 个画布像素；按键按下后在下一帧开始移动，松开方向键即停（自动收线除外），转向可发生在任意坐标。角色中心、边界和轨迹使用同一套坐标，不再使用格子、格点或步进吸附。

电脑、平板和手机的圈地、受击和得分提示统一显示在画面下方现有状态栏中，不覆盖画布、不占用手柄触区，也不改变游戏画面和手柄高度；短提示保留生命、分数和守卫血量，完整内容供辅助阅读工具读取。手机横屏采用紧凑布局，将画面与状态栏放在可见范围内，并预留安全区；横屏仍隐藏手柄。桌面显示完整提示，窄屏使用简短提示，完整内容仍供辅助阅读工具读取；提示始终位于画布外，旋转或缩放窗口也不会移回场内。

岸线行走允许自动走过单个修正段总绕行长度不超过 0.35 世界单位的微小台阶（864×576 参考画布约 4 像素，390 宽手机上约 1.65 CSS 像素）。修正跨越多个物理帧时会沿原方向继续完成，连续小起伏可逐段通过；只沿真实连通的岸线绕行，并消耗实际路程；明显台阶、真正拐角和断开的岸线不会自动跨越。小于 0.00001 世界单位的数值接触误差投影回真实岸线，闭合判断仍保持原有精度。地形面积与绘制保留原始连续几何，不把角色移动吸附到格点；子弹沿实际分段行走路线检测碰撞。

画线不能穿过仍然存在的旧线。按住画线键时，朝当前线段的反方向移动，会以普通移动速度沿该段退回并同步擦除线条；退到旧转角或出发岸边时停住，重新给方向可继续沿原路收线或改向续画。已经收掉的部分不再判定为活动轨迹，剩余线条和玩家仍可能受击，手动收线不增加面积或分数。画线尚未闭合时松开空格，角色会以画线速度的三倍沿原路连续退回，轨迹随线头逐段缩短，直到回到最初离开边界的点。回收无需按方向键。尚未返回起点时，再次按住空格、单手触控区或双手画线键，会立即停止回收；未给方向时停在线端，随后可以从当前线端继续画线。已经回收的部分保持消失，原出发点与剩余轨迹保留，松手后可再次回收。单独按方向键不会中断回收；完整返回后停在起点，重新按方向键开始下一次移动。回收不增加领地或得分，尚未收掉的线仍可被敌人击中。手机松开圆形画线键，或触摸被系统取消时，也会触发回收。切换操作方式、窗口失焦或切换宽屏会清除按键状态，避免卡键。暂停会冻结回收，继续后自动完成返程。受击后本次轨迹清空，返回出发点；闪烁恢复期间只能沿安全边缘移动。窗口失焦或切换标签页会自动暂停。音效默认关闭，可在侧栏开启。

## 开场选择

`src/faces.ts` 保存每张原图的像素尺寸及人工核对的头脸提取框，按图片路径绑定关卡。`/review/faces.html` 展示原图、提取结果和正方形禁区。更换角色图时必须重新标注，不可沿用旧图范围。

点击开始后，每秒轮换 30 个候选长方形。按空格、手机双手模式动作键或单手触控区确认当前矩形；5 秒内未确认则自动选定最后一个。候选期间没有玩家、敌人或子弹，游戏计时尚未开始，暂停和切到后台也会暂停选择。确认操作只选定起点，需要再次按住动作键才会开始画线。

矩形面积为地图的 0.1%–30%，采用 Beta(3,6) 分布映射到该区间，平均约 10%，较大的面积更少出现；若安全区域不足以容纳抽到的面积，则缩小到可容纳的上限。长宽与位置随机，位置会避开中央 Boss 和每关从原图逐张提取的头脸正方形禁区（包含耳朵、角和下巴，以头脸框较长边的 1.1 倍为边长，仅保留每侧约 5% 的余量，并与岛屿保留 0.25 世界单位的小幅间距（标准 72×48 地图），边和角都不能触碰），预览与最终选定都不会揭露脸部，并为场地四周保留通行空间。选定后该面积直接计入圈占进度，开场不赠送分数；玩家随机出生在矩形的一条边上，然后才生成 Boss 与本关配置数量的三类普通敌人（第一关各 2 个）。敌人按可见大小避开已圈占矩形、玩家及彼此。重开重新选择矩形。

引擎通过 `GameOptions.opening: true` 开启这一流程，页面已默认开启；独立规则测试可关闭。极小的自定义地图无法容纳常规候选时，在避开脸部与 Boss 的安全区域内缩小矩形，仍经过选择、岛岸出生和延迟生成敌人的流程，不回退到外框开局。面积、矩形生成与出生点共用 `GameOptions.random`，固定种子配合相同选择时刻可复现整局。

初始小岛之外没有可靠岸的外框。拉线碰到画面边缘时停在边缘，不出界、不结算、不加分，轨迹保持未闭合；可以保持画线并沿场边转向，最终接回真实岛岸，也可以松开空格沿原路回收。触摸取消同样回收。岛屿扩张触及外框后，与外框重合的真实岛岸会连续显示并可通行，包括已经覆盖的角落；普通行走到岛岸端点即停；按住画线可以从真实贴边岛岸向未圈区域起笔，包括沿场边继续拉线。新线仍处于危险状态，必须回到真实岛岸才闭合，松开或触摸取消则回收，裸露外框不会变成安全岸线。蓝灰色、无发光的外侧边框标示场地范围；薄荷色发光线始终表示真实岛岸，两者留有细小间距以便分辨。

每次闭合只把新圈出的部分并入小岛，不重复计算旧岛，也不顺带揭开圈外空区。两个岸线绕行构成的候选先扣除已有岛屿；若确实得到两个有效新区域，选择面积较小者。仅在角点相接的区域也属于连通岸线，支持从其中一块起笔、到另一块闭合，包括连续多个角点连接；合并后移除内部边线，保持面积与得分一致。经过交叉点时，若转向略有越过且前方是已占领内部，会在 0.35 世界单位内沿真实岸线走回交点完成转向，消耗实际路程；向未圈区域起笔仍保持原位置，断开的边线不会吸附连接。支持凹形岛屿、连续扩张、回到原出发点及画线路径主动沿场边绕行，但场边本身绝不触发闭合。全部占领和碰撞采用连续多边形几何，没有栅格吸附。

实际页面始终启用 `opening: true` 的小岛流程；独立旧规则夹具可以关闭开场，用于回归原有输入、攻击和效果，不是页面中的可选玩法。

## 访客与 Boss

所有敌人只在未占领区域内沿自己的轨迹独立移动，不追踪玩家，也不沿玩家画出的线移动；身体遇到外框或新圈地边界会反弹。

| 访客 | 移动 | 标识 |
| --- | --- | --- |
| 疾行 | 快速直线，边缘反射 | 珊瑚红箭头 |
| 环游 | 较慢的连续环绕，碰边反弹后继续环绕 | 淡紫圆环 |
| 折光 | 中速移动，每约 0.72 秒交替折转 | 浅蓝菱形 |
| 湖心守卫 Boss | 缓慢直线反射，按血量切换 4 发交替弹幕、8 向散射与补怪 | 橙色六边形 |

Boss 释放前约 0.85 秒显示蓄力圆环和对应方向数的提示。子弹不受占领边界阻挡，可以穿过已揭开的区域；它们会击中玩家（包括安全边界上的玩家）和未闭合的线，飞出场地后自动清理。受击后仍有 1.5 秒保护时间。暂停会冻结敌人、蓄力和子弹；重开会重置全部状态，胜负确定后清除攻击。

画线必须从小岛的有效岸线离开，再接回有效岛岸。新区域按闭合几何结算，地图外框和圈外空区都不参与靠岸判定。其中的普通敌人立即消失，每只奖励 500 分，并在原位置播放对应颜色的礼花与得分提示。另一侧或其他独立危险区中的敌人不受影响。若两个有效候选等面积，则采用稳定顺序选择其中一个，未选择的水域不结算。未闭合、正在回收、自交失败或受击中断的线都不能触发击杀。圈地碰撞先于奖励结算，整条活动轨迹（包括回收中剩余的线）都不能被敌人或子弹碰到。

Boss 默认有 5 格血。圈住 Boss 的小区域会被占领，Boss 只受击一次，奖励 250 分，然后跳向其他危险区中能容纳自身的安全位置。跃起时放大、落下时恢复原尺寸，并显示落地点阴影与受击光环。空中 Boss 不碰撞、不发射技能，重复圈住其预留落点会重新选择位置，不能在同一次跳跃里重复扣血。落地前会重新检查边界、玩家、其他敌人和新拉出的线；没有安全位置时保持无碰撞悬空并限频重试，玩家仍可通过占地达标通关。

Boss 血量归零奖励 2000 分并通关；占地达到 75% 也可直接通关。Boss 非致命受击时，已有子弹继续飞行，胜负确定时才统一清理攻击。减少动态效果时关闭爆散粒子及跳跃放大，保留淡出提示和位置变化。

敌人短尾迹仅表示它们刚走过的路线，不能供玩家行走或收线。圈地判定不将子弹视为区域占用者，成功圈地不会清除已有子弹。

## 结构

`Game.boundarySegments` 在页面的小岛模式下只返回已揭示岛屿的真实外轮廓，用于绘制、沿线行走和起笔/闭合检查。岛屿贴在地图边缘的部分也在这组岸线中；裸露外框不会被加入。敌人仍使用剩余危险区的完整边缘（包含场地外框）反弹，两者用途明确分开。接岸和起笔时，处于既有几何容差内的坐标会精确投影到连续岸线或顶点，避免近岸误差留下不可见细缝和内部残线；不做格点或像素吸附。新扩张后，旧的内部岸线自动消失；若有效连接点因完成整个独立区域而消失，则接到最近的有效岛岸并更新收线锚点。几何合并、差集与裁剪使用 `polygon-clipping` 的连续多边形布尔运算，未引入格子或像素掩码。

场地最外围提示线与真实世界边界重合，使用 1 个画布像素、25% 不透明度且不发光的细线；不再向外偏移形成视觉间隙。可行走的绿色岸线绘制在其上方，保留原有亮度，接近场地边缘时仍能清楚辨认。

- `src/island.ts`：岛屿合并、闭合候选、连续几何裁剪与真实岸线；处理多个水域和孔洞。
- `src/engine.ts`：连续坐标状态机，包含沿线移动、多边形切分圈地、敌人反弹、线段碰撞和胜负判定。
- `src/enemies.ts`：三种独立运动规则、Boss 本体运动和有长度上限的尾迹。
- `src/boss.ts`：Boss 血量/阶段配置、跳跃轨迹和危险区安全落点查找。
- `src/attacks.ts`：可替换的 Boss 技能、通用攻击物生命周期、可配置散射与十字/X 交替实现。
- `src/render-enemies.ts`：敌人形状、尾迹和 Boss 蓄力绘制。
- `src/geometry.ts`：线段距离、边界射线、面积与多边形切分；不使用栅格或像素掩码判定领地。
- `src/opening.ts`：候选矩形面积分布、30 Hz 选择、5 秒上限与边缘出生点。
- `src/effects.ts`：主题配置与圈地效果接口。静谧之湖主题先让新占领区域显白约 0.23 秒，再播放约 1 秒的湖光粒子消散；粒子上限为 180 个。系统启用减少动态效果时使用低强度淡出，不播放粒子。
- `src/joystick.ts`：单手触点位移向量、微抖累计过滤与稳定正交映射，独立于双手方向键判定。
- `src/main.ts`：Canvas 绘制、键盘与触屏输入、界面、可选 Web Audio 音效。
- `src/style.css`：响应式深色街机界面。
- `public/landscape.svg`：随领地揭开的原创风景插画。

当前包含十个主题关卡、选关、通关解锁和本地图鉴进度；各关 Boss 五格血、玩家三条生命。尚未加入云存档或排行榜。

`Enemy.radius` 是身体对活动轨迹和边界的碰撞半径，`visualRadius` 是独立的主体绘制半径。Boss 的六边形主体半径为 2（此前 1.18），碰撞圆半径为 1.65，位于六边形内；外围光环和蓄力提示属于装饰。Boss 初始位置和跳跃落点为可视主体留出空间，边缘反弹和轨迹碰撞使用较小的碰撞圆，避免玩家新圈出的边界落在可视边缘时将 Boss 卡住；跃起的放大不会扩大碰撞圈。子弹保留自己的半径和扫掠碰撞，不随 Boss 放大。圈地仍按封闭区域与敌人中心归属结算，未闭合线碰到碰撞圆时先判受击。初始敌人避开边界和 Boss，小尺寸测试地图使用有限搜索避免重叠；每个敌人有独立的运动和尾迹状态。

每局 Boss 从场地正中心开始，普通敌人在剩余未占领场地内随机出生。初始生成按可视主体检查：距边界至少保留 0.16、敌人之间及与 Boss 之间至少保留 0.25、距玩家除双方半径外额外保留 3 个世界单位。同类敌人的初始方向使用分段角度与随机偏移；速度与直线/环绕/折线规则按本关配置，环绕转向与折线起始节奏也独立随机。

`GameOptions.random` 同时供开局生成、后续 Boss 落点和补怪使用，默认 `Math.random`；测试可传入独立的固定种子生成器（返回 `[0, 1)`），相同种子完整复现，连续使用同一生成器的新局会继续取样。重开使用新的随机布局。每个初始敌人最多随机尝试 96 次，失败后搜索至多 2048 个几何候选点；极小的自定义场地若没有安全位置，就跳过放不下的敌人，不牺牲间距或阻塞启动。标准 72 × 48 场地按本关配置生成，第一关为三类各 2 个。

## 替换主题效果

`GameTheme.createCaptureEffect(region, reducedMotion)` 接收刚占领的多边形，返回实现 `update(seconds)`、`render(context)` 与 `finished` 的 `CaptureEffect`。绘制上下文使用与角色、边界一致的世界坐标。可在 `src/effects.ts` 新建主题并在 `src/main.ts` 选择它；主题可替换风景、场地外框颜色 `arenaBorder`、岸线颜色、轨迹颜色和整个圈地效果，无需修改圈地规则。重新开始会清除效果，暂停会冻结效果，胜利弹窗会等待最后一次效果结束再显示。

击败礼花通过 `GameTheme.createDefeatEffect(enemy, reducedMotion)` 替换，接收敌人类型、原坐标与奖励分数；Boss 受击光环通过 `createBossHitEffect(hit, reducedMotion)` 替换。它们与圈地效果共享 `CaptureEffect` 的生命周期，暂停会冻结、重开会清空，胜利结果等待效果结束后显示。

## Boss 血量、胜利条件与阶段测试

`GameOptions.bossConfig` 支持 `maxHealth`、`jumpDuration` 和 `phases`；默认值为 5 格血、0.9 秒跳跃、无额外阶段。`victory` 支持 `territoryPercent`（默认 75）、`territory` 与 `defeatBoss` 两条路线开关（默认都启用），可分别测试只看地图百分比、只看 Boss 血量或两者并用。

阶段按配置顺序升级，每项包含 `id`、`when.healthAtMost`、`when.territoryAtLeast` 以及可选 `createAttack`、`reinforcements`。同时给出血量和地图阈值时，两者都满足才触发。阶段工厂只在首次进入时创建，不会在每帧重置技能。

实际第一关通过 `gameOptionsFor` / `bossConfigFor` 适配 `lakeBossConfig` 模板：5–4 格血为一阶段，每 5 秒发射 4 发，第一波十字、第二波 X 字交替；3–2 格为二阶段，每 5 秒发射 8 向子弹；1 格为三阶段，每 2.5 秒发射 8 向子弹。预警方向与即将发射的一波一致；同阶段受击跳跃会冻结并保留波次，重开从十字第一波开始。二、三阶段每 6 秒最多补 1 个普通敌人，全程上限 6 个。新敌人交替沿水平、垂直路径以速度 8 往返（单只补充也延续方向次序），沿用疾行的外观与 500 分击杀奖励；初始三类敌人各 2 个。未适配的基础模板仍保留旧的 9/15 目标，供独立引擎兼容测试使用，不直接作为第一关配置。

补怪规则为 `reinforcements: { targetCount, interval, speed, motion, batchSize? }`，目标数量须为 0–32 的整数；可选 `batchSize` 是 1–32 的整数，限制一个周期最多新增多少只，省略时补满缺额。`motion: 'axes'` 交替补充水平和垂直运动的小怪；省略或设为 `'vertical'` 可兼容只沿垂直方向的其他关卡。刷新周期只在 Boss 落地且游戏进行时计时；切换阶段重置周期，暂停、跃起、胜利、失败或 Boss 已被击败时停止补怪。每次刷新只补缺额，生成位置须在未占领区域内，避开玩家、完整活动线和已有身体；无安全位置就推迟至下一周期，不强行塞入。`RadialAttack(directions, interval, warningSeconds, speed, angleOffsets)` 可配置弹幕及每波的角度序列，`AlternatingCrossAttack` 使用 `[0, π/4]` 实现十字/X 交替，切换阶段时既有子弹继续飞行，子弹数量和尾迹仍保留上限。原有占地百分比通关条件不变。

```ts
new Game(72, 48, {
  bossConfig: {
    maxHealth: 5,
    phases: [
      { id: '二阶段', when: { healthAtMost: 3 }, createAttack: secondAttackFactory },
      { id: '三阶段', when: { healthAtMost: 1, territoryAtLeast: 50 }, createAttack: thirdAttackFactory },
    ],
  },
  victory: { territoryPercent: 75, territory: true, defeatBoss: true },
});
```

落点搜索采用有限随机采样与几何扫描线回退，不会把 Boss 放进已占领区域或狭窄到容纳不下自身的位置。测试关卡设计仍需为 Boss 留出可落地区域；无落点时悬空重试，默认关卡可继续通过地图百分比通关。

## 替换 Boss 技能

`new Game(width, height, { createBossAttack: () => new MySkill() })` 为每局创建独立的 `BossAttack`。技能提供 `name`、`warning`（0–1 蓄力进度）和 `update(seconds, context)`；`context` 提供 Boss 当前位置、场地尺寸、`spawn(hazard)` 和 `cast()`，没有玩家追踪逻辑。

`AttackHazard` 约定攻击物的 `update`、`expired`、`hitsPlayer(from, to, radius)`、`hitsTrail(trail, radius)`、`onHit()` 和 `render()`。子弹、近战扇形、冲击波等均可实现这一接口，游戏主循环无需判断攻击类型。移动攻击需在碰撞方法内覆盖一帧经过的路径；本帧碰撞检查完毕后移除 `expired` 攻击物。默认 `Projectile` 使用扫掠碰撞，避免高速子弹穿过细线或边界上的玩家。近身技能的测试实现验证了非子弹攻击同样可用。

活动攻击物上限为 128，每个敌人的尾迹上限为 18 个采样点，过期攻击每个物理子步都会移除。更换关卡可通过 `GameOptions.enemies`、`boss` 和 `createBossAttack` 配置生成内容；若只需身体接触攻击，可提供 `() => ({ name: '普通攻击', warning: 0, update() {} })`，不生成额外攻击物。主题也可在 `GameTheme.createBossAttack` 提供技能工厂，当前湖主题已通过该入口创建四发交替弹幕；圈地视觉效果仍通过独立的 `createCaptureEffect` 替换。

## 发布到 GitHub Pages

仓库内置 `.github/workflows/deploy.yml`。首次发布时，在 GitHub 仓库的 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。推送到 `main` 会自动安装依赖、运行规则测试、构建并部署静态站点，也可以在 **Actions → Deploy LinkBlock to GitHub Pages → Run workflow** 手动运行。若启用 Pages 之前的部署已失败，启用后重新运行该工作流。

部署成功后，默认访问地址为 <https://roukeiyu.github.io/LinkBlock/>（以 GitHub 部署结果显示的地址为准）。资源使用相对路径，支持 GitHub Pages 项目目录。Actions 构建失败时不会部署新的版本。
